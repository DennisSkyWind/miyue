## 二、小红书 1：反共识型（强钩子）

```
【标题】
做了20年信息化，我发现90%的企业把数据治理顺序搞反了

【正文】
"先做主数据治理，搞清楚主数据，再做其他数据治理。"

这句话是不是很耳熟？
几乎每本数据治理的书都这么写。

但我今天要说的，可能和你听到的不一样：

❌ 主数据治理不是数据治理的起点
✅ 它是数据治理摸清家底之后的第一个突破口

为什么？

因为主数据清单，根本不是"规划"出来的，是"盘"出来的。

你以为的主数据，要看过全量数据才能确认：
• 你以为的客户主数据，财务系统里叫"往来单位"
• 你以为消灭掉的重复，某历史系统里还躺着3万条
• 你以为该治的"非主数据"，其实是另一个部门的核心主数据

这些靠调研问不出来，只能靠数据碰面。

而"数据碰面"这件事，就是数据入湖。
数据入湖，本身就已经是数据治理的开始。

那什么时候能先做主数据？
看你的数据成熟度：
L0 没体系 → 先建体系，别急着治
L1 有制度没全景 → 先入湖盘点
L2 有全景有标准 → 可以从主数据切入，但清单要复核
L3 治理已常态化 → 不存在起点问题，只有排期问题

一句话：
你不可能在没看过全量数据之前，宣布哪些数据是主数据。
```

## 三、小红书 2：管理者视角型（对话感）

```
【标题】
老板问"数据治理从哪开始"，别再回答"先做主数据"

【正文】
上周跟一个企业数据负责人聊，他说：
"我们领导批了主数据这块预算，不先做主数据说不过去。"

我给他的回答是三句话：

第一句：主数据治理是数据治理的必经环节，这话没错。
第二句：但主数据清单不是规划出来的，是盘点出来的。
在数据全量见面之前，你定出来的清单只是照搬经验，
范围很可能第一天就错了。
第三句：所以顺序是——
数据入湖 → 资产盘点 → 问题清单 → 指标筛出治理范围 → 主数据治理。

看起来慢一步，但省掉的是后面全部的返工。

第三句是关键。

因为预算批的是"做主数据治理"这件事，
不是"现在就能定出主数据清单"。
第一步的交付物应该是盘点报告，不是主数据清单。

还有个更隐蔽的坑：
很多企业的主数据平台建起来了，
但没人回答过——
"这个平台里装的主数据清单，
是盘点出来的，还是照搬来的？"

如果是照搬的，那它装的只是一个从未被检验的假设。
```

```
"先做主数据治理，再做其他数据治理"——这是行业默认共识。

主数据清单不是规划出来的，是盘出来的。

L0 先建体系 / L1 先入湖盘点 / L2 可切入但清单要复核 / L3 无起点只有排期

主数据治理不是数据治理的起点，
是数据治理摸清家底之后的第一个突破口。
```

## 五、微博 2（反常识切口）

```
【正文】
一个反常识的判断：
数据治理一定先于主数据治理启动。

为什么？因为主数据治理只是数据治理的一个环节、一个必经之路。

而且主数据清单靠两样东西才能确定：
① 数据入湖——让全量数据碰面，问题自己暴露
② 指标——筛出真的主数据，确认范围、时机、深度

没这两样，你定的主数据清单
只是"上一家药企这么做，所以我们也这么做"。

抄别人的顺序，等于抄了别人的前提条件。
```

## 六、微博 3（决策清单型，实用向）

```
【正文】
管理者自查：你的企业该从哪开始做数据治理？

L0 没有制度、没有专门组织、没有资产清单
→ 先建体系：制度 → 组织 → 摸家底
（常见错误：上来就买平台、就定标准）

L1 有《数据管理办法》有数据办，但说不清有多少数据、在哪些系统
→ 先入湖 + 资产盘点：让数据见面
（常见错误：直接挑主数据开工）

L2 资产清楚、标准成体系、平台在跑
→ 主数据治理可以作为突破口，但范围须由指标复核
（常见错误：把已有清单当定论，不再验证）

L3 治理已是日常运营、按业务价值滚动排期
→ 不存在起点问题，只有排期问题
（常见错误：还在纠结"先做什么"）

一句话版：
L0 先确权建组织，别急着治具体数据
L1 先让数据见面，再谈治谁
L2 可以从主数据切入，但用指标复核范围
L3 别再把主数据治理当"项目"做

#数据治理 #主数据 #数据资产盘点
```
