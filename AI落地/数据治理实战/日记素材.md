## 日记1：数据治理——先内后外，顺序不能颠倒

**标签**：[[数据治理]] [[方法论]] [[CIO]] [[企业数字化]]

### 核心观点

很多公司都有数字化部门，CIO 请咨询公司来做方案然后上系统实施。
这个思路是对的，但也不完全正确。

### 为什么这样说？

**第三方咨询的角色应该是辅助，而不是主导。**

正确路径：
```
第一步：公司内部先做好三件事
    ├── 情况摸底（数据现状是什么）
    ├── 目标确定（数据治理要解决什么问题）
    └── 责权明确（谁负责、谁推动、谁考核）

第二步：成立数据组织
    └── 建立公司一级的数据治理委员会或专项小组

第三步：制定公司一级数据管理制度
    └── 明确数据标准、数据质量要求、数据安全规范

第四步：有了人和权之后
    └── 再请第三方咨询进来，配合实施
```

### 常见错误顺序

1. 先请咨询公司出方案
2. 方案做完才发现没有组织保障
3. 没有数据委员会，没有数据管理制度
4. 咨询公司走了，系统推不动

**结果：** 花了钱，没有效果。

### 关键原则

> 咨询公司是来帮你做技术方案和实施支持的，不是来帮你做组织保障的。
> 组织保障必须是自己公司的事情，必须先于咨询介入。

**先有人、有权、有制度 → 后有咨询、有系统、有工具**

核心原则：**先组织后技术，先治理后系统。**

## 日记2：数据治理重要的是管理体系而不是工具

**标签**：[[数据治理]] [[方法论]] [[工具误区]]

### 核心观点

就算没有数据治理平台，通过单纯数据库系统的各类功能也可以做治理。

### 常见误区

很多企业做数据治理，第一件事就是买平台。
**结果：** 平台上了没人用，制度没有，系统推不动。把工具当成解药。

### 没有平台也能做治理

| 治理动作 | 工具方法 |
|---------|---------|
| 数据标准定义 | 数据库字段命名规范 + CHECK约束 |
| 数据质量检查 | SQL定期查询 + 自动化脚本 |
| 数据安全 | 数据库用户权限管理 + 审计日志 |
| 主数据管理 | 数据库分区 + 唯一索引约束 |
| 数据血缘 | ER图 + 文档记录 |
| 数据资产盘点 | 数据库字典 + 定期巡检 |

**本质：制度和流程到位了，工具只是锦上添花。**

### 正确优先级

```
第一步：建立数据管理制度（人）
第二步：明确数据Owner职责（权）
第三步：制定数据标准规范（法）
第四步：选型数据治理工具（器）
```

**器最后。**

### 金句

> 好的数据治理不需要平台，需要的是对的人、对的制度、对的方法。
