### 要点 1｜营销 AI 助手：全书唯一一个完整失败案例
> 来源：`素材资料/61_老周口述_营销AI助手项目失败复盘.md` → 已写成第八章 8.5

```
营销部门 + IT 部门联合研发，给一线做助手：
  ① 知识库：制度政策解读 / 销售政策与销售方案解读 / 产品信息
  ② 数据：一线随时查自己的销售数据，管理层也能查
功能做出来了 → 但：
  · 数据不完整或不满足业务需求 → 用户不喜爱
  · 客户端接入：一线习惯微信类工具，公司红线禁止公司数据外传 → 出错、出问题
```

**★ 书里提炼的三条可署名判断：**
- 数据类 AI 场景的第一性问题不是"能不能查"，是"查出来的数是不是他心里的那个数"
- "要实时"和"要完整"在多数系统里互斥——先承认这一点，再谈需求
- 一线不用你的工具，不是因为懒，是因为你的工具不在他的工作流里；**当合规红线把"唯一正确的路径"和"最顺手的路径"分开时，失败的不是用户，是设计**

### 要点 5｜★ 制造业六环节的 AI 适合度（新增 8.0.1）
> 来源：32 号 + 老周"制造业通用"口径 → 已写成第八章 8.0.1、引言新增段

```
   研发 → 采购 → 生产 → 库存 → 质量 → 销售
```

| 环节 | AI 适合度 | 典型结局 |
|---|---|---|
| 研发 | 差（验证周期长） | 试点悬空 |
| **采购** | ★ 最好 | **最容易先成功** |
| 生产 | 差（实时与完整互斥） | 卡在数据侧 |
| 库存 | 中 | 卡在口径统一 |
| 质量 | 中（责任不可转移） | 必须配套留痕与签字设计 |
| **销售·文档** | ★ 好 | **可做**（合同智审已覆盖销售合同与协议，全公司覆盖） |
| **销售·数据** | ★ 差 | **典型失败**（8.5 营销助手 / 8.6 智能问数） |

**★ 普适结论：AI 落地的顺序，不该从"最痛的地方"开始，而该从"规则最明确的地方"开始。**
因为"痛"不等于"适合"——最痛的地方往往同时是：口径说不清、入口改不动、效果验不了。

**★ 而最有力的一组对照：同一个部门、同一批人，一件事做成了（合同智审全公司覆盖）、一件事没做成（营销助手、智能问数）——差别不在部门，在"规则 vs 口径""文档 vs 数据"。**
