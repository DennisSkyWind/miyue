## 附录 A　场景评估表（业务价值 × 可行性 打分模板）

**来源**：作者的实践做法是——把所有候选场景列成清单，逐条按"值不值得做"打分，而不是凭印象挑几个。素材中记录的规模是**七十余条候选需求逐条打分**【待核实：具体条数以作者最终确认为准】。

### A.1 评分表（可复制）

```
┌────┬────────────────┬──────────┬──────────┬──────────┬────────┐
│ #  │ 场景            │ 业务价值  │ 可行性    │ 优先级    │ 结论   │
│    │                │ (1-5)    │ (1-5)    │ =价值×可行性│        │
├────┼────────────────┼──────────┼──────────┼──────────┼────────┤
│ 1  │                │          │          │          │ 做/缓  │
├────┼────────────────┼──────────┼──────────┼──────────┼────────┤
│ 2  │                │          │          │          │ 做/缓  │
├────┼────────────────┼──────────┼──────────┼──────────┼────────┤
│ …  │                │          │          │          │        │
└────┴────────────────┴──────────┴──────────┴──────────┴────────┘
```

### A.2 价值怎么打分（5 分定义）

| 分 | 判据（业务价值） |
|---|---|
| 5 | 直接影响收入、成本或合规风险，且**有明确的责任人**（做错了谁赔） |
| 4 | 明显减少重复劳动，替代人力明确 |
| 3 | 效率提升，但受益人分散、价值难量化 |
| 2 | 锦上添花，做不做都能活 |
| 1 | 说不清收益 |

### A.3 可行性怎么打分（5 分定义）

| 分 | 判据（可行性） |
|---|---|
| 5 | 数据现成、口径唯一、流程已有负责人 |
| 4 | 数据现成，但口径需对齐一次 |
| 3 | 数据在两个系统内可取，需开发 |
| 2 | 数据需跨系统整合或需外部采购 |
| 1 | 数据不存在或口径混乱 |

### A.4 收敛规则（★ 这一步才是重点）

```
优先级 = 价值 × 可行性

≥ 15  → 进入候选池（第一批做 1–2 个）
9–14  → 备选（第一批跑通后接着做）
< 9   → 暂不做（写进清单，半年后重评）

★ 但最终只选 1–2 个进入试点，其余全部留在清单里
```

**"选完不删表"很重要**：被搁置的场景留在清单上，下次复盘时重评，而不是每次重新想一遍。

### A.5 一条使用提醒

> **这张表最重要的一列不是分数，是"结论"列里的"为什么不做"。**
>
> 如果 20 个场景里有 18 个写的是"暂不做"却没写原因，那么三个月后你会重新讨论这 18 个场景。

## 附录 C　AI 模型与工具台账模板

**素材状态**：素材库中**没有**《AI模型管理规范》原件正文【待核实：需作者提供或确认按本模板代替】。以下模板按通用工程实践编写，供作者替换。

### C.1 台账字段

```
┌────┬──────────┬────────┬────────┬────────┬────────┬────────┐
│ #  │ 名称/用途  │ 类型    │ 版本   │ 责任人 │ 上线日  │ 状态   │
├────┼──────────┼────────┼────────┼────────┼────────┼────────┤
│ 1  │          │        │        │        │        │在用/退役│
└────┴──────────┴────────┴────────┴────────┴────────┴────────┘
```

### C.2 每个条目要补的六项

| 项 | 内容 | 为什么必须有 |
|---|---|---|
| **数据边界** | 哪些数据会进它、哪些不出厂 | 出事时第一句话就是问这个 |
| **权限与可见范围** | 谁能用、谁能看它处理过什么 | 权限继承的落点 |
| **日志留存** | 输入/输出/调用人/时间存多久、谁能查 | 审计与追溯 |
| **降级方案** | 它挂了怎么办，谁接手 | 兜底不是可选项 |
| **复核机制** | 谁定期看它的输出、抽查多少 | 防止它悄悄变差 |
| **退役条件** | 什么情况下下线、下线后数据怎么办 | 防止僵尸工具累积 |

### C.3 退役条件（建议写法）

```
出现下列任一情况 → 启动复核 → 决定整改或退役：
  ① 连续 N 个月价值类指标低于初始目标的 50%
  ② 人工介入次数持续上升（说明模型在退化或场景在漂移）
  ③ 依赖的上游系统已下线
  ④ 出现合规问题且无法通过整改闭环
  ⑤ 场景的业务流程已不存在
```

> 【待核实】退役条件中的 N 值与"人工介入次数上升"的判定口径，需按作者所在企业的管理制度确定。

## 附录 E　风险自查清单

**自检方式**：每一条打"是/否/部分"。**任何一个"否"且该风险不可接受，就先别上线。**

```
【数据与合规】
  □ 出厂的数据已逐项分级（可进 / 需脱敏 / 绝对不进）
  □ "绝对不进"的数据，确实没有以任何形式（含摘要）出厂
  □ 个人信息已脱敏或聚合化处理
  □ 检索权限过滤发生在检索之前，而不是生成之后
  □ 输出必须带出处，且无出处时明确拒答

【责任与流程】
  □ 每个结论有明确签字人（AI 辅助，不是 AI 决策）
  □ 错误上报 → 纠错 → 回流的路径已跑通至少一次
  □ 复核能力已复制到推广后的岗位（不依赖能人）

【技术运行】
  □ 模型/工具台账已建立，含数据边界、责任人、退役条件
  □ 降级方案已演练过（工具不可用时怎么办）
  □ 日志留存策略已定，且与供应商条款一致
  □ 模型换版本后做过回归抽查（行为漂移）

【组织】
  □ 推广期有"长期负责人"的名字，不是岗位
  □ 收益兑现去向已写明
  □ 涉及个人行为感知的场景，已写明"不做个人持续监控"的边界并公开
```

## 附录 F　常用技术名词速查（给不写代码的读者）

| 名词 | 一句话解释 | 读者最该关心的一点 |
|---|---|---|
| **大模型 / LLM** | 从海量文本里学出来的"下一个词预测器"，靠它组出像人话的答案 | 它不保证正确，只保证像人话 |
| **Token（令牌）** | 模型处理文本的最小计量单位，中文大约 1 个字≈1–2 个 token | 计费与上下文长度都按它算 |
| **上下文窗口** | 模型一次能"看到"的文字总量 | 超出窗口的内容它完全不知道 → 这就是 RAG 存在的理由 |
| **Embedding（嵌入/向量化）** | 把一段文字变成一串数字，意思相近的文字数字也相近 | 靠它做"语义检索" |
| **向量数据库** | 专门存这些数字并做相似度检索的数据库 | 知识库的底座；**它不保证权限正确** |
| **RAG（检索增强生成）** | 先从知识库捞出相关片段，再连同问题一起给模型，让它照着答 | **它把"模型不知道"变成"模型查得到"，但不负责查得对** |
| **切片（Chunking）** | 把长文档切成小段，分别建索引 | **切得不好，后面全错**；切片里必须带生效期 |
| **混合检索** | 关键词检索 + 语义检索一起用 | 制度类文件里，关键词比语义更可靠 |
| **微调（Fine-tuning）** | 用你自己的数据再训练模型，让它更懂你的风格与格式 | **它改不了模型的知识时效**，知识要变就用 RAG |
| **Agent（智能体）** | 能自己拆任务、调用工具、多步完成一件事的模型应用 | 它让 AI 从"回答"变成"办事"，也把风险从"答错"升级成"做错" |
| **MCP** | 一种让 AI 以标准方式连接企业工具与数据源的协议 | **标准化的意义是权限与审计可以统一做** |
| **私有化部署 / API** | 模型跑在自己机房，或调用云端服务 | 决定"数据出不出厂"；**它是数据边界问题，不是性能问题** |
| **幻觉** | 模型一本正经地说错话或编造事实 | 只能靠**引用溯源 + 拒答 + 人工确认点**控制，不能靠提示词消除 |
| **置信度** | 模型对本次答案的把握程度（估算值，不是保证） | **低置信度时不给结论、只列分歧点**，是高管场景的关键设计 |
| **Token 成本 / 调用量** | 按输入输出量计费或占用算力 | **它决定了"能不能规模化"，也决定了哪些场景值得私有化** |

**F.1 一张选型速查表**

```
问自己四个问题：

  知识经常变吗？     → 变 → RAG（别去微调知识）
  要的是风格和格式吗？ → 是 → 少量微调
  要多步自主完成吗？   → 是 → Agent（并严格限定工具权限）
  数据能出厂吗？       → 不能 → 私有化 / 分片外发 / 路由
```
