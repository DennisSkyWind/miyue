## 一、老周原话（2026-11-02）

> 2025 年黄掉的场景，有一个是 **C 端的 AI 机器人**，也就是**数字员工的一种用法**。
>
> 前面提到我们在做数字员工，**对内**有很多场景，**对外**（对 C 端或供应商）也想做一个数字员工，
> 来解决 AI 应用落地的问题。
>
> 过程中考虑了**穿戴设备、智能屏、虚拟数字人**等一系列方式，
> 希望形成 **AI 应用模式的转变和营销模式的变化**，
> 把**线下变线上**，**数据回流**，**沉淀知识**，促进**销售**和**用户体验**。
>
> 规划时跟**国内头部大厂**合作，最终发现几个问题：
> 一是 **AI 技术整体不成熟**；
> 二是**企业内部数据沉淀和管理模式不成熟，无法适应新模式**；
> 三是**前期投入大、周期长，效果不明显，可能只是散在小事点上的创新，不能带来本质变化**。

## 二、★ 三个失败原因，是这本书目前最完整的一次失败归因

```
★ 原因一：AI 技术整体不成熟
   → 这是"外部条件不成熟"，不是你的错，也更不该由你承担风险

★ 原因二：★ 企业内部数据沉淀和管理模式不成熟，无法适应新模式
   → ★★ 这是最要命的一条 —— 它是【甲方自己的问题】
   → ★★ 而这一条，只有甲方自己会说出来。
        乙方不会说，因为说出来就等于说"你们家底不行，别做"
        大厂不会说，因为那是他们的客户，不便评价
        → ★ 于是这本书成了唯一能说这句话的地方

★ 原因三：前期投入大、周期长，效果不明显，
        可能只是散在小事点上的创新，不能带来本质变化
   → ★ "不能带来本质变化" —— 这句话是整个案例的灵魂
```

**★ 为什么这三条归因比"失败了"本身更有价值：**

```
它给出了一条通用判据（可以贴在墙上）：

★ 一个 AI 方向该不该做，看三件事：
   ① 技术条件成熟了吗？（不成熟 → 等，或者找不依赖它的做法）
   ② ★ 内部的数据和管理，配得上这个新模式吗？
      （配不上 → 这不是技术问题，是你还没准备好）
   ③ ★ 它带来的是"本质变化"还是"小事点上的创新"？
      （★ 只能带来小事点上的创新 → 那就不叫战略，那是碎片）
```

## 三、★ 这个案例补上了 8.1 的第三档

```
★ 8.1 原来的论证（缺一半）：
   46 个"计划做" ＋ 23 个"已实现" ＝ 零重叠
   → 有"做成的"和"没做的"，但没有"黄掉的"

★ 补上第三档之后的完整结构：

   做成并活下来      → 23 个（且 83% 在办公域）
   计划中没动        → 46 个
   ★ ★ 曾经规划、投了人、最后散了 → ★ 这一档之前是空的
        ↓
★ 而"这一档是空的"本身就是结论的一部分：
   ★ 很多方向不是被否决的，是自然消散的 ——
   ★ 没有结论，没有复盘，也没有写进任何一份材料
```

**★ 为什么"自然消散"比"明确否决"更值得警惕：**

```
★ 明确否决的项目：有一个结论，有一次决策，有一个人负责
★ 自然消散的项目：投入已经花掉了，但没人说得清它算什么
        ↓
★ 而"自然消散"的项目，会在第二年以"我们还在探索"的形式重新出现
★ —— 直到某一天它变成一笔说不清的沉没成本
```

## 四、★ 失败的三个层次（本案例带来的新框架）

| | 8.5 营销助手 | **8.5.2 C 端数字员工** | 8.6 智能问数 |
|---|---|---|---|
| **失败在哪一层** | 场景层（选错了场景） | ★ **方向层（这件事本身就不该做）** | 试探层（试了，不成，认了） |
| **典型原因** | 数据口径不对 + 入口与红线冲突 | ★ 技术不成熟 + 内部底子不配 + 只能带来碎片 | 价值未被认可，需求本身不足 |
| **投入规模** | 中（做了功能、有人用了一小阵） | ★ **大**（多载体、多目标、跟大厂合作） | 小 |
| **周期** | 短（上线 3 个月即无人使用） | ★ **长** | 短 |
| **结束方式** | 拖了约 1 年才停投入 | ★ **散**（没走完立项/评审流程就没了） | 明确承认后停 |
| **留下的东西** | 负资产（系统还在线，无人使用） | ★ **只有一份 PPT 和一些会议** | ★ **一个清楚的结论** |
| **损失** | 中 | ★ **最大**（投入大、周期长、什么都没留下） | 最小 |
| **★ 最容易被掩盖吗** | 中 | ★ **最容易**（可以说"我们在探索前沿"） | 最难（结论清楚） |

**★ 由此得出全书一条新的排序结论：**

> **★ 试探性失败最便宜，方向性失败最贵——而且方向性失败最不容易被察觉。**
>
> **★ 因为它没有"失败"的样子。它看起来像"在探索"。**

## 五、★ 可提炼的普适结论（入稿用）

**结论一：★ 载体先行，是这类项目最典型的死法。**

```
★ 当年的路径：先考虑载体（穿戴设备 / 智能屏 / 虚拟数字人），
   再往里填内容
        ↓
★ 正确的路径：先想清楚"哪个业务动作需要被数字化"，
   再决定用什么载体
        ↓
★ 载体是手段，不是方向。
★ 先定载体的人，会被载体绑架——
   然后发现每种载体都要投一大笔钱，
   而每一种都只能做到"小事点上的创新"
```

**结论二：★ "把线下变线上"是最容易讲的故事，但数据回流有前提。**

```
★ "把线下变线上，数据回流，沉淀知识" —— 这套话听起来无懈可击
        ↓
★ 但"回流"的前提是：线下业务本身已经产生了结构化数据
   如果线下的动作还发生在纸单、微信、口头里，
   那就没有东西可以"回流"
        ↓
★ ★ 而"沉淀知识"的前提更严：
   你得先有一个被公认的知识来源（制度、流程、专家），
   否则沉淀下来的是一堆没人认的垃圾
```

**结论三：★ 一个方向要改变的东西越多，越可能一件都改不成。**

```
★ 当年那个方向，同时想要五样东西：
   ① AI 应用模式转变 ② 营销模式变化 ③ 线下变线上
   ④ 数据回流 ⑤ 沉淀知识促进销售与体验
        ↓
★ ★ 而最后落点其实是 ⑥"促进销售和用户体验"
   —— 从"改变模式"退回到"促进某个指标"
        ↓
★ 教训：★ 一个项目如果同时要改变五件事，
   那它一件都没打算真改变
```
