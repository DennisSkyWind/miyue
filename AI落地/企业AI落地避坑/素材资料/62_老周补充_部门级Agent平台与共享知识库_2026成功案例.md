## 三、★ 这个案例真正的价值：它是"平台型成功"，和前两个不是一类

```
合同智审、印章识别  =  ★ 单点场景成功（一个工具解决一个问题）
部门级 Agent 平台   =  ★ 底座型成功（给一个部门建一套共用能力）
        ↓
★ 前两个证明"AI 能做成事"，这一个证明"AI 能做成组织能力"
```

**为什么这个案例值得单独写一节（三条理由）：**

**理由一：它回答了第一章坑四"员工抵触"的一个正面解法。**
坑四说员工抵触来自"系统不是我的工作流"。而部门级 Agent 平台的解法是：
**把 Agent 建在部门内部，用部门自己的知识库**——它不需要员工改变工作流，
因为它就在部门里，用的是部门的话、事、规矩。

**理由二：它证明了"开源替代"这条路走得通。**
A5/A6 是关键：**用开源免费项目 QwenPaw + DeepSeek Harness 搭出公司内智能体平台**，
而不是买 WorkBuddy 这类商业平台。
→ 32 号 P4 明确写了这条的成本逻辑：**通过自主推进降低 AI 建设成本（咨询 50~100 万 → 自主推进）**
→ 这与第六章"算账"直接呼应：**平台型能力的自建 vs 外采，是这本书写过的最重要的一次采购决策。**

**理由三：它把 8.0.1 的六环节判断落到了实处。**
研发中心做成了 LLM-WIKI 知识助手（A2/A3）——为什么研发中心在 8.0.1 里被标为"AI 适合度差"？
**因为它做的不是"研发算法"，而是"研发文档与知识的管理"。**
> **★ 这一点让 8.0.1 的结论更精确了：**
> **同一个部门里，文档密集的活适合 AI，验证周期长的活不适合。**
> **判断的单位不是"部门"，是"环节里具体哪件事"。**
> **这条正好呼应 8.0.1 那句"按规则密度找场景不会失败"——研发中心的知识管理就是高规则密度的活。**
