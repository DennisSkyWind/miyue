### 要点 1｜MCP：接得上 ≠ 敢让它接
> 来源：`/home/ubuntu/logseq-notes/mcp协议是什么.md` → 已写入第四章 4.3

```
MCP = Model Context Protocol（Anthropic 2024-11 开源，非"多路径控制协议"）
三角色：Host（AI 应用）→ Client（与某个 Server 一对一）→ Server（提供能力）
双能力面：Tools（模型可调用的动作）／ Resources（可读数据）／ Prompts（预置模板）
传输：本地 stdio，远程 Streamable HTTP（2025-06 规范取代 SSE）

★ 企业落地要点（两条硬要求）：
   权限代理 —— 模型只能看到该用户有权看的数据
   审计留痕 —— 谁、何时、调了哪个工具、返回了什么
★ 与 Agent 的关系：MCP 是工具接入的标准管道，Agent 是决策调度层。
   先有稳定的工具接口，再谈自主 Agent。
★ 选型时该问的一句："你们的工具接入是不是走 MCP 标准？"
   非标准接口 = 新的锁定。
```

### 要点 2｜RAG 失败九成不是模型问题，是检索问题
> 来源：`/home/ubuntu/logseq-notes/rag技术原理.md` → 对应第三章 3.3

```
RAG = 先查资料，再让模型基于查到的资料回答
四环节：切分 Chunking → 向量 Embedding → 检索（向量+BM25 混合排序）→ 生成

★ 为什么企业首选 RAG 而不是微调：
   微调改变模型"怎么说"，RAG 改变模型"知道什么"
   企业知识三个月一变，微调根本追不上；RAG 改一次索引全员生效
★ 数据治理的落点（本书第三章的立论）：
   检索质量直接取决于文档的元数据、版本、权限标注是否规范
   文档没有所有者、没有版本、没有生效失效日期 → RAG 一定把过期版本喂给模型
★ 五个常见坑：
   只做向量不做混合检索 → 精确词（产品编码、批号、人名）召回极差
   按固定字符数切片 → 表格和条款被切坏
   不做权限过滤 → 越权泄露
   不管版本时效 → 答案基于作废文件
   不做召回评测 → 改 Prompt 全靠感觉，无法定位问题
```
